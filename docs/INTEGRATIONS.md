# Integrations and operational boundaries

Documentation reviewed during 21–24 October 2026. The application uses one Next.js app. Provider clients and credentials stay in server modules. Nothing in this repository creates a provider account, deploys an app, performs app review, or sends a live test message automatically.

## Configuration and truthful states

`DEMO_MODE=true` gives the isolated synthetic business adapter. Social-account and database authorization are disabled in this demo. Seeded social conversations are labelled synthetic; they do not represent connected accounts. `AI_PROVIDER=demo` is an explicit independent setting, also usable on a personal hosted instance. Missing provider configuration fails with an actionable error and never becomes a fake successful connection. `BILLING_PROVIDER=mock` does not enable real AI.

The manager-only integration API returns safe source/connection status, import previews, pending authorized asset choices, jobs, outbox metadata and cost accounting. It never returns encrypted credentials, OAuth verifiers or model keys. Agents may reply in their authorized inbox; they cannot configure secrets.

## DeepSeek and retrieval

Current official [first-call documentation](https://api-docs.deepseek.com/) identifies `deepseek-flash` as the economical model name, currently served by DeepSeek-V4.1-Flash-1017. The integration uses the official HTTPS `/chat/completions` endpoint, non-thinking mode, JSON output, no model tools, a 350-token output ceiling, bounded evidence, a 20-second timeout and one attempt. The [request reference](https://api-docs.deepseek.com/api/create-chat-completion/) and [JSON guide](https://api-docs.deepseek.com/guides/json_mode/) were checked; legacy `deepseek-chat` is not the default.

Model output can select only validated source IDs and request handover. Server code renders approved facts, catalog prices, stock freshness and rules. This deliberately restricts generative paraphrasing: it avoids trusting a model-generated confidence score or allowing invented prices. Catalog facts are structured; only published same-business knowledge participates; date rules use half-open `[start,end)` intervals. The model cannot choose another business, run SQL, invoke code, place orders, collect payments or disclose private order records. Active rules cannot be removed by model selection. Conflicting equal-priority rules hand over. Exact SKU matching and normalized Bangla/Banglish aliases supplement lexical search. This is lexical retrieval, not semantic vector search. The optional embedding interface does not pretend that the chat API produces embeddings.

Reply templates support English, Bangla and Banglish. A uniquely identified size/variant uses its own price and stock; unspecified or ambiguous variants trigger clarification rather than an unrelated base price. Currency formatting uses the catalog currency. Approved policy text remains in its authored language; automatic freeform policy translation is intentionally not claimed. The 30-case evaluation fixture checks expected source IDs, prices, privacy, stale/unknown stock and calendar boundaries. It is an application-grounding evaluation, not a live DeepSeek benchmark.

Real inference requires all of:

- `AI_PROVIDER=deepseek`, `REAL_INFERENCE_ENABLED=true`, a server-only `DEEPSEEK_API_KEY`, the official `DEEPSEEK_BASE_URL`, and `DEEPSEEK_MODEL`.
- Operator-supplied current uncached input/output rates in integer USD micro-units per million tokens: `DEEPSEEK_INPUT_USD_MICROS_PER_MILLION` and `DEEPSEEK_OUTPUT_USD_MICROS_PER_MILLION`.
- Independent positive integer daily budgets: `AI_TEST_DAILY_BUDGET_USD_MICROS`, `AI_IMPORT_DAILY_BUDGET_USD_MICROS`, `AI_BUSINESS_DAILY_BUDGET_USD_MICROS`, `AI_GLOBAL_DAILY_BUDGET_USD_MICROS`. One USD is 1,000,000 micro-units. Days use UTC for operator accounting, separately from the business's display timezone.

Before the call, a conservative worst-case token cost is reserved atomically both per business and globally. Model usage settles that reservation; ambiguous transport failure retains the maximum cost reservation. A mock purchase cannot change these limits. Actual provider rates are configured rather than guessed; Meta charges remain separate and unknown unless an operator supplies diagnostics. Obvious import mappings are deterministic. An optional DeepSeek mapping suggestion sends only column headers and two short, redacted sample rows, uses a separate import budget and a 500-token output ceiling, and can return only existing column names for known fields. It cannot write records. Owners review the suggestion before publishing. Imports are capped at 20 previews and 10 mapping suggestions per business per day; no AI-generated SQL is executed.

## Data sources and imports

Inline CSV and XLSX uploads are capped at 2 MB. Configured production Storage supports signed direct file uploads up to 20 MiB; the isolated demo remains limited to 2 MiB. All paths retain limits of 2,000 rows, 40 columns and 4,000 characters per cell. XLSX is checked before parsing: central-directory bounds, entry counts, expanded size, compression ratio and bounded inflation of actual entries. Formula, hyperlink and error cells are rejected. Macro formats are unsupported. Exported spreadsheet-like strings must pass `spreadsheetSafe` to prevent formula injection. Downloadable CSV and XLSX samples are under `public/samples`; regenerate the XLSX with `node scripts/generate-sample-xlsx.mjs`.

Mappings are editable and versioned. IDs/SKUs must be stable; prices are explicit decimal values, currency must be explicit, and stock is a whole number or unknown. “Available” does not become a guessed quantity. Businesses default to BDT and can select USD/EUR/GBP/INR before catalog creation. An import currency that differs from the business is rejected; no conversion or silent relabeling occurs. Original rows, hashes, mapping, errors and up to 20 recent review batches persist privately. All invalid rows must be corrected before publication. Retrying an already published identical snapshot is idempotent. Replacements upsert by source plus source-record ID. Explicit owner field overrides survive sync. Missing records can be retired only from a complete successful snapshot, with owner opt-in. Bounded Google range results never authorize inferred deletions.

Documents support UTF-8 TXT/Markdown and text-based PDFs, limited to 50 pages and 80,000 extracted characters. Scans return an OCR-required error; there is no OCR service. Document chunks and historical chat pairs are drafts until explicitly published. The documented chat formats are in [fixtures/README.md](../fixtures/README.md). Redaction of email, Bangladesh phone and common order/address references is only a first pass: the owner must review personal details and one-off discounts. Raw history is never a shared answer source.

Small uploads pass through a bounded function request. Larger supported production files first call `/api/assets` with `action: prepare`, upload directly to the returned signed Storage URL, and call `action: complete` to verify the stored bytes. The import route then accepts `{action:"asset",assetId,kind,sourceId?}` and loads only an authenticated same-business verified asset. Parsing is synchronous but bounded by file, extraction, row and archive limits; there is no arbitrary-size or streaming import claim. Configure the private `business-files` bucket using the ordered migrations. The Settings file list can remove unused uploads; see SECURITY for signed-capability expiry and deletion semantics.

Remote catalog image URLs remain quarantined and are never fetched. Merchant PNG/JPEG/WebP images can be privately uploaded through the Catalog editor (5 MiB production, 2 MiB demo), verified, and explicitly approved for customer delivery. Social delivery uses the common PNG/JPEG subset up to 5 MiB and only when the customer requests a picture of one uniquely identified approved product. The server resolves a five-minute signed URL immediately before the send and rechecks approval at the final gate. SVG sample illustrations and WebP files are not sent as social attachments. Revoking approval stops queued delivery; a signed URL already issued or provider-held copy follows its remaining expiry/provider retention.

### Google Sheets

The operator creates a Google OAuth web client, enables Sheets API, configures `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` and the exact callback:

`https://YOUR_STABLE_ORIGIN/api/integrations/oauth/google/callback`

The merchant uses Connect and selects a spreadsheet by ID and worksheet name. The [official OAuth authorization-code flow](https://developers.google.com/identity/protocols/oauth2/web-server) uses one-use actor-bound state, PKCE, offline access and the read-only `spreadsheets.readonly` scope. That scope covers accessible spreadsheets, so the app limits runtime reads to the selected ID; it never calls a write endpoint. Google verification may be required for public use. Credentials and refresh tokens are encrypted; revoked/expired grants produce a reconnect state.

Reads use the documented [Sheets values.get API](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get), bounded `A1:AN2002`, rows dimension, unformatted values, size limits and timeout. More than 2,000 records is a reported failure. A worksheet/file change requires a new selected source and review. Every sync retains errors and preserves the last successful catalog; failed/partial snapshots do not remove products.

### PostgreSQL and MySQL

Create a dedicated SELECT-only user for an explicit table or view and the selected columns, with a unique stable key. Do not use an administrator account. PostgreSQL administrative roles are rejected. Each adapter enforces a read-only repeatable snapshot transaction, parameterized pagination, strict identifiers, connection/query timeouts and TLS certificate validation. User-controlled SQL is never accepted. PostgreSQL uses `pg`; MySQL uses `mysql2/promise`. [node-postgres client options](https://node-postgres.com/apis/client), [query parameters](https://node-postgres.com/features/queries) and [mysql2 connection configuration](https://sidorares.github.io/node-mysql2/docs/examples/connections/create-connection) informed these adapters.

The hostname must resolve entirely to public unicast addresses. The checked IP is pinned at connection time while preserving TLS hostname verification. Private, loopback, metadata, link-local and mixed DNS answers are rejected. A tunnel/private-network connector is not implemented. Use a narrowly restricted TLS endpoint reachable from your deployment, approved egress networking and database-level least privilege; never expose an unrestricted database or disable TLS. At most 2,000 rows are read in 250-row pages. Read-only views can bound larger catalogs. Optional disposable SQL fixture definitions are provided; no real database connector was live-tested.

`/api/integrations/cron` requires `Authorization: Bearer CRON_SECRET`. It maintains at most 100 businesses and starts at most 20 source workflows per invocation. Maintenance applies subscription expiry and conversation retention, drops expired OAuth attempts, marks sends stalled for over two minutes as uncertain, and releases inference reservations with no saved outbound reply after 30 minutes while handing the conversation to staff. It never repeats a send or an uncertain inference. Ambiguous delivery retains reserved quota until operator reconciliation, except when the owner's retention period removes its customer records; then uncommitted quota is released without claiming that delivery failed. Only connected sources with an approved mapping qualify for sync. Review batches with errors stay unpublished; subsequent successful syncs can reuse the confirmed mapping. Configure the scheduler manually at an interval compatible with the chosen Vercel plan. Larger installations need a partitioned scheduler. Manual sync obeys the plan's minimum sync interval.

## Meta operator setup

Set `META_APP_ID`, `META_APP_SECRET`, `META_GRAPH_VERSION`, `META_WEBHOOK_VERIFY_TOKEN`, `META_MESSENGER_CONFIG_ID`, `META_WHATSAPP_CONFIG_ID`; direct Instagram Login uses its own `INSTAGRAM_APP_ID` and `INSTAGRAM_APP_SECRET`. The Graph version must be set explicitly to the version available to your reviewed app; sample fixtures use v25.0 solely to validate request shapes. Do not interpret a fixture version as a successful live endpoint test.

Register these stable HTTPS webhook URLs:

| Channel   | Webhook                   | Callback                                                                          |
| --------- | ------------------------- | --------------------------------------------------------------------------------- |
| Messenger | `/api/webhooks/messenger` | `/api/integrations/oauth/messenger/callback`                                      |
| Instagram | `/api/webhooks/instagram` | `/api/integrations/oauth/instagram/callback`                                      |
| WhatsApp  | `/api/webhooks/whatsapp`  | Embedded Signup code completes through authenticated `/api/integrations/channels` |

GET verification compares the configured challenge token. POST uses the correct app secret and HMAC-SHA256 over raw request bytes; the verification token alone cannot authenticate it. Events are capped at 1 MB, normalized, tenant-resolved from a globally unique authorized asset mapping and durably persisted before acknowledgment. Payload business IDs are never trusted as authorization.

The operator must configure a Meta business app, privacy policy, deletion instructions/callback requirements, test users/assets, business verification where required, necessary advanced permissions and app review. Prepare review videos showing Connect, account selection, message handling, handover and disconnect. Development mode only reaches eligible test users/assets. Deployment does not grant Meta approval. Check conversation routing and other installed inbox integrations before activating this assistant. No blanket historical-message import or universal existing-number migration is promised.

Meta's developer documentation returned access restrictions/HTTP 429 during this build. Endpoint shapes and direct-Instagram permission names were additionally checked against **Meta's own official Postman collections**, not third-party tutorials. The inaccessible platform-specific review and policy pages must be verified again in the operator's app dashboard before live enablement:

- [Messenger platform](https://developers.facebook.com/documentation/business-messaging/messenger-platform/) and [Meta's Page token discovery example](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api?entity=request-23987686-1ff01566-3509-48bd-a0f4-8571a91ccfdf).
- [Direct Instagram Login platform](https://developers.facebook.com/documentation/instagram-platform/) and [Meta's Instagram messaging collection](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api?entity=request-23987686-e2cfad80-45dd-4111-9ac4-9ae96b9d7ed0).
- [WhatsApp Embedded Signup](https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview), [official Cloud API registration](https://www.postman.com/meta/whatsapp-business-platform/request/zb2u18b/register-phone) and [Meta's current registration/Cloud API collection](https://www.postman.com/meta/whatsapp-business-platform/documentation/wlk6lh4/whatsapp-cloud-api?entity=request-13382743-9dbec0ce-30d4-4df2-b188-674b7d8da2d9).

### Messenger

Facebook Login for Business requests `pages_show_list`, `pages_messaging`, `pages_manage_metadata` using the operator's login configuration. The backend validates app-issued tokens and scopes, lists authorized Pages and verifies the user's Page messaging/manage task. The owner selects a Page, which is claimed uniquely for that business, subscribed and verified. A redirect alone does not mark it connected. Sending uses the Page access token and `/{PAGE_ID}/messages` with `messaging_type=RESPONSE`. Automation remains paused until explicitly activated. Page discovery is capped at 100; larger grants require narrowing authorized Pages.

### Instagram

The chosen route is **Instagram Login for professional Business/Creator accounts**. It requests only `instagram_business_basic` and `instagram_business_manage_messages`. It does not require a linked Facebook Page and does not mix Facebook Login scope names or Page tokens into this route. The server exchanges the authorization code, obtains a long-lived token, discovers the professional account through `graph.instagram.com`, subscribes and sends through that same API host. Tokens nearing expiry are refreshed server-side; revoked/expired access requires reconnect. Text is split at 1,000 UTF-8 bytes without breaking Unicode code points. Approved image attachments use the Instagram send payload; incoming image understanding, transcription and group messaging are unsupported. Recheck the [official Send Messages reference](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/messaging-api/send-messages) for the Graph version selected by your reviewed app.

### WhatsApp

The browser starts official Embedded Signup using the operator's Facebook Login configuration and returns an authorization code. The server consumes one-use state, exchanges the code, validates the app/scopes, derives authorized WABA IDs from token granular grants and discovers phones through those WABAs. A browser-supplied phone/WABA ID is never accepted on its own as proof of access.

Selection subscribes the app to the WABA and registers the phone through `/{PHONE_ID}/register`. The six-digit WhatsApp two-step PIN is sent directly from the authenticated server operation to Meta; it is never saved or added to Workflow arguments. Owners must retain it securely themselves. Existing business-app coexistence, migrations and account-specific onboarding may require provider-side setup and can return a clear error. This release implements the ordinary Cloud API registration route and does not claim every coexistence/migration configuration works.

Free-form replies use `/{PHONE_ID}/messages`. Once the 24-hour customer service window has elapsed, the server returns `whatsapp_template_required`. A template selection/sending UI is not implemented; staff must use an approved provider workflow for that case. This exception is not applied to Messenger or Instagram.

## Delivery, handover and Workflows

`workflow` is configured through the Next.js wrapper. `src/workflows/messages.ts` uses stable `'use workflow'`/`'use step'` and `start()` APIs confirmed in [Vercel Workflows](https://vercel.com/docs/workflows) and the [Workflow SDK source](https://github.com/vercel/workflow). This implementation does not require experimental dynamic workflows. Check the lockfile for the installed version. The provider's infrastructure, retention, limits and usage charges remain separate from this application's plans.

Workflow arguments contain only business, job or response IDs. Credentials are loaded privately inside steps, never serialized as recorded arguments/results. A persistent inbox deduplicates channel+asset+event IDs; conversation leases prevent overlapping generation. Outbox records reserve a stable response ID before inference and recheck automation generation, connection state, response window and current rules immediately before sending. Echoes from other staff take over. Unsupported attachments are handed to staff. A later provider failure reverses a billable acceptance at most once; status updates never downgrade delivered/read records.

Queue delivery does **not** make a non-idempotent provider send exactly once. A timeout, 5xx, malformed acceptance or crash after send begins becomes `ambiguous`, with no automatic resend. The manager must inspect the provider inbox and reconcile accepted (with the verified provider message ID) or failed. Only prepared unsent outbound records and pending/expired-lease inbound jobs may be restarted through `/api/integrations/jobs`. Real inference with an uncertain previous attempt is not automatically repeated. Prepare steps retry at most twice; inference/send steps do not retry irreversible side effects. Reserved usage remains pending for an ambiguous send until reconciliation.

A long text or text-plus-image answer is one logical response with one usage reservation. Bubbles are delivered in order. An uncertain bubble blocks every later bubble; a failed bubble cancels unsent siblings. Usage commits only after the entire response is accepted, and later definitive failure reverses it at most once. After confirming an uncertain bubble as accepted, the owner can resume its remaining prepared siblings. Human staff text uses the same channel length/splitting rules without consuming AI reply quota.

The Channels test action checks credential/asset/subscription access only and never sends a customer test message. Live-message testing requires the operator's explicit approval and eligible test recipients.

## Website widget

The owner supplies exact HTTPS origins, activates the widget and copies the installation script. The loader creates an isolated iframe, bounded mobile layout and accessible chat controls. The frame uses a nonce CSP and exact `frame-ancestors`. Public random widget IDs map server-side to a business. Sessions are hashed, expire after 24 hours and bind to a particular widget/business, session and origin; chat and polling are rate limited. Retries reuse stable request IDs and do not double charge. Disabling a widget removes its sessions.

An origin allowlist is abuse reduction, **not customer authentication**. Public visitors can read only approved public catalog/knowledge. Private orders, payments and account data always require verified staff assistance. No privileged tokens, customer history from other sessions or source diagnostics are returned. Replies are rendered with `textContent`, not HTML. Staff replies remain visible through scoped polling.

## Credential lifecycle and validation status

`CREDENTIAL_ENCRYPTION_KEY` is a server-only base64 encoding of exactly 32 random bytes. AES-256-GCM binds ciphertext to business and credential ID with authenticated context. Keep the key in a secrets manager or protected deployment environment. Rotation requires a controlled maintenance migration that decrypts with the old key and re-encrypts with the new key; there is no silent automatic rotation. Keep encrypted backups and the correct key separately. Disconnect immediately disables local sends, removes the usable credential and asset mapping, then attempts provider unsubscription. Provider failure is reported with instructions to revoke in provider settings. Data deletion must also follow the deployment/security runbook and provider retention limits.

Tests are isolated fixtures with injected transports, deterministic AI and in-memory persistence. They cover signatures, all channel payload shapes, ambiguity, duplicate events, takeover, tenant scoping, review/upsert behavior, private-address rejection, hostile inputs, cost boundaries and widget sessions. Live Meta, Google, SQL, Supabase and DeepSeek verification requires real credentials and the user's approval; it was not performed. The build report records actual test execution separately from tests merely present in source.
